Plain Markdown is fine for prose, but tutorials usually need more: a warning that stands apart from the surrounding paragraph, or install steps that differ by package manager. MDX lets a document mix JSX components into Markdown, so a tutorial can drop a callout or a tabbed code sample straight into the prose without importing anything by hand.

This article is itself an `.mdx` file, and every box below is real output, not a screenshot.

## Callouts

Use `<Callout>` to flag something the reader shouldn't skim past. The `type` prop picks the color and default label; `title` overrides the label if you need something more specific.

<Callout type="note">
  Callouts accept regular Markdown in their body, including `inline code`, **bold text**, and
  [links](/).
</Callout>

<Callout type="tip">
  Skip the `type` prop entirely for a plain note, or set it to `tip`, `warning`, or `danger`
  depending on how loud the moment needs to be.
</Callout>

<Callout type="warning" title="Before you continue">
  `title` is optional. Pass it when the default label ("Note", "Tip", "Warning", "Important")
  doesn't fit what you're saying.
</Callout>

<Callout type="danger">
  Reserve this one for actions that are hard to undo, like deleting content or shipping a breaking
  config change.
</Callout>

## Tabbed code samples

Use `<CodeGroup>` with `<CodeGroupItem>` children to show the same step across a few variants, like package managers, without repeating the surrounding prose three times.

<CodeGroup>
<CodeGroupItem label="npm">

```bash
npm install
npm run dev
```

</CodeGroupItem>
<CodeGroupItem label="pnpm">

```bash
pnpm install
pnpm dev
```

</CodeGroupItem>
<CodeGroupItem label="yarn">

```bash
yarn install
yarn dev
```

</CodeGroupItem>
</CodeGroup>

The tabs are progressive enhancement: a small inline script builds the tab list and hides the inactive panels on load. Without JavaScript, every panel still renders in order with a visible label, so the content stays readable either way.

## Syntax highlighting

Ordinary fenced code blocks don't need a component at all. Markdown and MDX posts both render through Shiki with a dual light/dark theme, so a plain code block already follows whichever color mode the reader has picked:

```ts
export function greet(name: string) {
  return `Hello, ${name}`;
}
```

## Building your own

Neither component is exotic. A callout is an element with a variant class and a title; a tab group is a container of labelled panels plus a little script that shows one at a time. Neither needs a build step of its own.

The detail worth copying is theming. Drive the colors from tokens instead of fixed values, so a callout picks up light and dark mode the same way the surrounding page does.
